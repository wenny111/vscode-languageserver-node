# Testbed 启动指南

## 🚀 快速启动

### 首次启动（必须执行）

```bash
# 在项目根目录执行
# 1. 创建符号链接
npm run symlink:testbed

# 2. 编译所有依赖模块
npm run compile

# 3. 编译 testbed
cd testbed
npm run compile
```

### 日常启动

```bash
# 在 testbed 目录
npm run compile
# 然后在 VSCode 中按 F5
```

## 🔧 调试配置

### Launch Client（启动客户端）

- **作用**: 启动一个新的 VSCode 窗口，加载 testbed 扩展
- **使用场景**: 测试扩展功能
- **启动方式**: 按 `F5` 或选择 "Launch Client" 配置

### Attach to Server（附加到服务器）

- **作用**: 附加调试器到运行中的语言服务器进程
- **使用场景**: 调试服务器端代码
- **启动方式**:
  1. 先启动 "Launch Client"（这会启动服务器并监听端口 6012）
  2. 然后启动 "Attach to Server"（端口 6012）
- **注意**: 确保端口号与客户端代码中的 `--inspect` 端口一致（默认 6012）

## ❌ 常见错误及解决方法

### 错误: Cannot find module 'vscode-languageclient/node'

**原因**:
- 符号链接未创建
- client 模块未编译

**解决**:
```bash
# 在项目根目录
npm run symlink:testbed
npm run compile:client
cd testbed
npm run compile
```

### 错误: Extension activation failed

**原因**:
- testbed 未编译
- 依赖模块缺失

**解决**:
```bash
# 检查编译状态
cd testbed
npm run compile

# 检查输出文件是否存在
# testbed/client/out/extension.js
# testbed/server/out/server.js
```

### 错误: Server failed to start

**原因**:
- 服务器模块未编译
- 路径配置错误

**解决**:
```bash
# 编译服务器
npm run compile:server

# 检查服务器文件
# testbed/server/out/server.js
```

### 错误: TypeError: folders is not iterable

**原因**:
- `getWorkspaceFolders()` 可能返回 `null`，代码没有进行空值检查

**解决**:
- 此问题已在代码中修复，确保使用最新代码
- 如果仍有问题，检查 `testbed/server/src/server.ts` 第 199-203 行是否有空值检查

### 错误: Notification defines parameters by name but received parameters by position

**原因**:
- 客户端和服务器端的通知参数结构不匹配
- `ProtocolNotificationType` 默认使用 `byName`，而 `NotificationType` 默认使用 `auto`（数组会变成 `byPosition`）

**解决**:
- 此问题已在代码中修复，统一使用 `byPosition`
- 如果仍有问题，检查客户端和服务器端的通知类型定义是否一致

## 📝 验证步骤

启动成功后，你应该能够：

1. ✅ 看到新的 VSCode 窗口打开
2. ✅ 在新窗口中打开 `testbed/workspace` 目录
3. ✅ 打开 `.bat` 文件时看到语言服务器功能（补全、悬停等）
4. ✅ 在命令面板中看到 testbed 相关命令

## 🔍 调试技巧

1. **查看输出**: 在新窗口中打开"输出"面板，选择 "Testbed" 或 "Language Server" 查看日志
2. **设置断点**: 在 `testbed/client/src/extension.ts` 或 `testbed/server/src/server.ts` 中设置断点
3. **检查连接**: 确保客户端和服务器通过 IPC 正常通信
